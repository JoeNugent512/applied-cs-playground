# Lab 14: BUILD a Power App with AI

This is the fictional **Team Explorer** learning kit for Lab 14. It supports a
small, read-only directory/skills-finder example and the repeatable workflow:

**B — Blueprint the Data · U — UI Mockup · I — Inform the AI · L — Launch the
Build · D — Debug with Evidence**

The files are references for Power Apps Studio and an external AI assistant.
They do not connect to SharePoint, Microsoft Lists, an AI service, or real
people. No Copilot license is required.

## Suggested order

### Optional instructor preparation

An instructor may prepare an authorized, nonproduction practice List and a
blank responsive Canvas app. This is optional: a learner can create both
during practice if time and permissions allow.

1. Create/configure the `TeamMembers` List using the schema below.
2. Keep the autogenerated `ID` Number column. Never import fixture IDs into a
   live List's ID column.
3. Leave the built-in `Title` single-line text column optional and unused.
   Create a separate single-line text column named `Name`; do not rename or
   repurpose `Title` as `Name`.
4. Add the remaining columns with the simple documented types:
   `JobTitle`, `Team`, `Location`, and `Email` are single-line text;
   `ProfileImage` is plain multiline text containing a self-contained
   `data:image/svg+xml` image data URL; `Education`, `Skills`, `Expertise`,
   `Tools`, `Certifications`, `Bio`, and `AskMeAbout` are plain multiline text.
   Do not configure `ProfileImage` as a SharePoint Hyperlink, Image, or Person
   column.
5. Configure the columns before importing rows. CSV values do not create or
   prove SharePoint types.
6. Use only the fictional rows in this kit. Never add real employee details,
   tenant URLs, credentials, or production records.
7. Optionally create a blank responsive Canvas app connected to `TeamMembers`.
   Leave the learner an empty directory screen such as `scrTeamExplorer`, not
   a completed gallery or profile solution.
8. Test access with a learner account. Their own SharePoint connection may
   need to be established in Power Apps Studio.

Keep any app edit link out of this public kit. Keep an instructor copy or
version before sharing a prepared app.

### BUILD walkthrough

1. Open the Lab 14 lesson and explore the local Team Explorer directory.
2. Review the schema and ask why each field supports the directory. `Skills`
   is useful for search; **Favorite Pizza** is a deliberately irrelevant
   design-thinking example, not a graded question.
3. Give an external AI assistant the rulebook, the schema, and only fictional
   data. Use exact control and field names.
4. Build one small task at a time: search, team filter, profile navigation,
   profile details, clear filters, and skill tags.
5. Use `team-explorer.powerfx.txt` as a short reference, not as proof that a
   live List has the same internal names.
6. When behavior is wrong, record Expected, Actual, the current formula, and
   a small JSON projection. Form one hypothesis, make one change, and run the
   same test again.

The learner does not need to finish a production app or complete a giant final
challenge. The goal is a reusable development process, not a score.

## Canonical data shape and newline convention

Every field except `ID` is a string in the canonical Team Explorer model. The
JSON and CSV use the exact fields and values from `demos/teamData.ts`. In the
CSV, multiline values are quoted fields containing their original newline
characters:

```text
Skills: Python
Power Apps
Databases
Education: B.S. Computer Science
M.S. Data Science
```

Keep those strings unchanged when loading the List or local collection. The
browser and downloads intentionally share one canonical shape:
`ID`, `Name`, `JobTitle`, `Team`, `Education`, `Skills`, `Expertise`, `Tools`,
`Certifications`, `Location`, `Email`, `Bio`, `AskMeAbout`, and `ProfileImage`.
`Team` is plain text. `ProfileImage` is plain multiline text containing a local
self-contained data-SVG image data URL; bind that stored text directly to a
Power Apps Image property. It is not a SharePoint Hyperlink or Image column.
The built-in `Title` column is documented in the schema as optional/unused, but
is not part of the canonical dataset.

## Naming contract

Use these names while building the example so prompts and formulas have useful
context:

| Purpose | Name |
| --- | --- |
| List/data source | `TeamMembers` |
| Directory gallery | `galTeamMembers` |
| Search input | `txtSearch` |
| Team filter | `drpTeam` |
| Selected record | `varSelectedEmployee` |
| Directory screen | `scrTeamExplorer` |
| Profile screen | `scrProfile` |

Good names make formulas easier for the learner, teammates, future developers,
and AI to read. Read generated code before using it; AI is a tool, not the
developer.

## Copy and JSON

`JSON` and `Copy` are behavior functions. Put a formula such as
`Copy(JSON(MyCol))` on a button's `OnSelect` property, where `MyCol` means a
collection. Do not put it in a label or gallery `Items` property.

The Power Fx reference includes a safe concrete projection:

```powerfx
Copy(
    JSON(
        ShowColumns(TeamMembers, ID, Name, JobTitle, Team, Skills, Expertise),
        JSONFormat.IndentFour
    )
)
```

The projection excludes image/media and unrelated profile details. If
clipboard access is blocked, set a `varDebugJSON` variable from the same JSON
expression, display it in a multiline text input, and copy the visible text
manually. Copy may not work when Power Apps is embedded in Teams, SharePoint,
or Power BI.

## Evidence-first debugging

Use the worksheet for the modeled bug: **select Alex → see Jordan**. Inspect
one layer at a time:

1. Which gallery record was selected?
2. What value is in `varSelectedEmployee`?
3. Which formula assigned the variable?
4. What does the profile screen display?

Use the loop **Observe → Hypothesize → Test → Learn**, not random edits. A
useful request follows **Context + Code + Expected + Actual**. Protect a
working version, make one change, test, and keep or revert it.

## Safety and limits

- All people, addresses, biographies, skills, and avatars are fictional.
- This kit is read-only. Do not add `Patch`, submit, flow, Dataverse, or
  custom API behavior.
- A local browser demo does not prove live permissions, connector behavior,
  delegation, internal names, or production readiness.
- Use an approved practice environment and follow local data-handling rules.
- Formula examples use English-locale commas. Authoring locales may use
  semicolons.

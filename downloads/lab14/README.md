# Lab 14 learning kit

Use these files with Power Apps Studio and an external AI assistant. No Copilot-licensed feature is required.

## Suggested order

1. Paste `ai-project-rulebook.md` into a new AI conversation.
2. Create an authorized blank practice List using the steps below.
3. Record its schema, then export its deliberately fictional current view.
4. Give AI `requests-schema.json` plus the supplied sanitized CSV/JSON and ask it to generate the test collection.

## Create a safe practice List

Use an authorized SharePoint practice site or the Microsoft Lists app. Do not use a production site.

1. Choose **New list > Blank list**.
2. Name the list **Requests** and save it only in the approved location.
3. Keep the autogenerated **ID** Number column and built-in **Title** Text column.
4. Add **Description** as **Multiple lines of text**, plain text, optional.
5. Add **Status** as a single **Choice** column with exactly **Green**, **Yellow**, and **Red**.
6. Add **DueDate** as **Date and Time**.
7. Add **Owner** as a single **Person** column and make it optional.
8. Add **Completed** as **Yes/No** with default **No**.
9. Manually enter 2–3 fictional rows. Leave Owner blank, or use only an organization-approved real test account. Never invent a SharePoint Person identity.
10. Before export, record each column’s display name, internal name, exact type, single/multi setting, Choice values, and useful value fields from the real column settings.

Do not import the supplied CSV and assume its types were preserved. CSV strings do not create or prove Choice, Person, Date/Time, or Yes/No configuration.

If you cannot create a List, ask the instructor for an authorized practice List. You can still complete the local collection workflow with the kit, but do not claim you completed a real List export.

## Fixture facts

The fictional snapshot has 12 records. Eight are incomplete: Green 3, Yellow 3, Red 2. Four are completed. Dates are fixed around the class anchor September 8, 2026, so they are reproducible and are not relative to the day you open the file. The same IDs and values appear in CSV, JSON, and Power Fx.

Prompt AI to generate `ClearCollect(colTestRequests, ...)` from the supplied schema, CSV, and typed JSON first. Require all 12 records, Choice `{Value: ...}` records, the read-only Owner projection, Boolean Completed values, and Power Fx Date/Time values. Check its output against the known counts. The supplied `.powerfx.txt` file is the reference fallback, not the first step.

IDs 101–112 belong only to this local fixture. A live SharePoint List autogenerates IDs, so its IDs may differ.

## Export a real Microsoft List

First choose the view deliberately: expose the needed columns and apply only intended filters. An export reflects the current view. Export to CSV supports up to 30,000 rows.

Use **Export > Export to CSV** where available. Otherwise use **Export > Export to Excel**. SharePoint may download an `.iqy` file; that is an Excel connection instruction, not exported rows. Open it in Excel, allow/refresh the authorized connection, then use **Save As** to create `.xlsx` or CSV. Refresh is one-way: edits in Excel are not written back to the List.

Record the actual List column settings separately: display and internal names, exact types, single/multi settings, Choice values, and useful value fields. CSV contains flattened strings and does not prove that a field is Choice, Person, or Date/Time.

Sanitize before sharing with AI. Use fictional data only. Remove employee PII, secrets, tenant URLs, internal links, attachments, and unrelated columns. Inspect the final file yourself.

Official Microsoft source: [Export to Excel from SharePoint or Lists](https://support.microsoft.com/en-us/office/export-to-excel-from-sharepoint-or-lists-bfb2ea48-6118-4fa9-abb6-cced9424e5d9)

## Copy and JSON constraints

`JSON` and `Copy` are behavior functions, so place them in a behavior property such as a button's `OnSelect`. Use Studio preview or the direct web player for the Copy activity. `Copy` is not supported when Power Apps is embedded in Teams, SharePoint, or Power BI.

If `Copy` is blocked, use the fallback formula from the lesson to set `varDebugJSON`, set a multiline Text input's `Default` to `varDebugJSON`, then select and copy the visible text manually.

Use `ShowColumns` deliberately so unsupported or unnecessary fields are not silently included. The fixture projection omits Description and Owner because they are not needed for the filter diagnosis. JSON can emit logical column names when both display and logical names exist; inspect the actual output rather than assuming its keys.

Microsoft references:

- [Copy function](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-copy)
- [JSON function](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-json)

## Limits of this fixture

The JSON and Power Fx use a fictional, read-only Person projection with `DisplayName` and `Email`, and Choice with `Value`. Those fictional people are not valid identities in your tenant, and this is not a full SharePoint Person write payload. Leave Owner blank in a real practice List unless you have an organization-approved test account. Local collection success does not prove live-list internal names, delegation behavior, connector behavior, permissions, or production readiness.

Formula examples use commas for an English authoring locale. Your locale may use semicolons.
